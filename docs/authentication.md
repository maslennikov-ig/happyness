# Архитектура аутентификации в Happyness

## Обзор

Система аутентификации Happyness построена на основе современных подходов безопасности с использованием JWT (JSON Web Tokens) и реализует полный цикл управления аутентификацией пользователей, включая регистрацию, вход, обновление токенов, выход, смену пароля и защиту маршрутов.

## Ключевые компоненты

Система аутентификации состоит из следующих основных компонентов:

### Серверная часть (Backend)

- **AuthModule** - центральный модуль, объединяющий все компоненты аутентификации
- **AuthService** - сервис с бизнес-логикой аутентификации
- **JwtStrategy** - стратегия для проверки JWT токенов
- **LocalStrategy** - стратегия для аутентификации по email и паролю
- **TokenService** - сервис для управления токенами
- **AuthGuards** - гварды для защиты маршрутов
- **AuthController** - контроллер, предоставляющий API эндпоинты

### Клиентская часть (Frontend)

- **AuthProvider** - контекст-провайдер для управления состоянием аутентификации
- **TokenManager** - утилита для работы с токенами
- **AuthAPI** - API-клиент для взаимодействия с серверными эндпоинтами
- **AuthGuard** - компонент для защиты маршрутов на клиенте

## JWT-токены

Система использует два типа JWT-токенов:

- **Access токен** - короткоживущий токен (15-30 минут) для доступа к защищенным ресурсам
- **Refresh токен** - долгоживущий токен (7-30 дней) для обновления access токенов

## Безопасность

Архитектура системы аутентификации обеспечивает защиту от распространенных атак:

- **XSS (Cross-Site Scripting)** - использование HttpOnly куки и хранение токенов в памяти
- **CSRF (Cross-Site Request Forgery)** - использование SameSite куки и проверка Origin/Referer
- **Token theft** - механизм ротации refresh токенов и короткое время жизни access токенов
- **Brute force** - ограничение скорости запросов и блокировка после множественных неудачных попыток

## Интеграция с другими системами

Система аутентификации интегрируется с другими компонентами приложения:

- **UsersModule** - для управления пользователями и их данными
- **AuthorizationModule** - для управления правами доступа на основе ролей
- **AuditModule** - для отслеживания действий пользователей
- **NotificationModule** - для отправки уведомлений о событиях аутентификации

## Схема базы данных

Система аутентификации использует следующие модели данных:

- **User** - информация о пользователе
- **RefreshToken** - хранение информации о refresh токенах
- **LoginAttempt** - отслеживание попыток входа для защиты от брутфорса

## API эндпоинты

Основные эндпоинты API для аутентификации:

- `POST /api/v1/auth/register` - регистрация нового пользователя
- `POST /api/v1/auth/login` - вход пользователя
- `POST /api/v1/auth/refresh` - обновление токенов
- `POST /api/v1/auth/logout` - выход пользователя
- `GET /api/v1/auth/me` - получение информации о текущем пользователе
- `POST /api/v1/auth/change-password` - смена пароля пользователя
