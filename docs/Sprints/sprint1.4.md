## Основные цели спринта

1. Разработка системы авторизации и ролей
2. Определение API-контрактов для модулей
3. Начало работы над базовыми компонентами UI

## Межспринтовые зависимости

### Входящие зависимости

- task-1.3-1.1: Завершение разработки базовой системы аутентификации (для развития в полноценную систему авторизации и ролей)
- task-1.3-2.1: Продолжение работы над модульной архитектурой (для определения API-контрактов между модулями)

### Исходящие зависимости

- Система авторизации и ролей (task-1.4-1.1) будет использоваться в sprint1.5 при разработке механизма регистрации модулей и профилей пользователей
- API-контракты (task-1.4-2.1) будут использоваться во всех последующих спринтах для интеграции модулей
- Базовые UI компоненты (task-1.4-3.1) будут использоваться во всех последующих спринтах для разработки интерфейса

#### task-1.4-1.1: Разработка системы управления ролями и правами доступа

- **Ссылка на дорожную карту:** [Спринт 1.4](../Roadmap.md#спринт-14-05062025---11062025)
- **Зависимости:** task-1.3-1.1
- **Контекст и Цель:** На основе реализованной в предыдущем спринте базовой системы аутентификации необходимо разработать полноценную систему управления ролями и правами доступа, которая обеспечит разграничение функционала платформы между различными типами пользователей (Предприниматель, Сотрудник компании клиента, Консьерж-менеджер, Администратор платформы). Система должна обеспечивать гибкое управление доступом к ресурсам и функционалу приложения.

Разработаны соответствующие гарды и декораторы для NestJS, а также механизмы управления доступом на стороне клиента.
- **Ссылка на детализацию:** [Детальное описание и подзадачи](../tasks/tasks1.4/task-1.4-1.1.md)
- **Оценка Сложности (первичная):** Высокая
- **Тех. Указания (ключевые):** TypeScript, NestJS, Prisma, JWT, React/NextJS, RBAC (Role-Based Access Control)
- **Нефункциональные Требования (ключевые):**
  - Безопасность: строгая проверка прав на всех уровнях (API, бизнес-логика, UI)
  - Производительность: минимизация излишних проверок прав
  - Масштабируемость: возможность расширения системы ролей в будущем
- **Потенциальные риски:** Сложность в обеспечении правильного баланса между гранулярностью прав и производительностью системы
- **Интеграционные точки:** Система аутентификации, все модули системы, которые требуют проверки прав доступа
- **Вопросы для Уточнения (первичные):** Нужно ли реализовать управление динамическими правами (изменение прав через UI) или достаточно статической системы ролей на первом этапе?

  - Безопасность: строгая проверка прав доступа, аудит всех действий
