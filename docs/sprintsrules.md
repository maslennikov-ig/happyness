# Правила для ИИ по созданию файлов с описанием задач спринта (`sprint<N>.md`)

**Цель:** На основе краткого описания целей спринта из `Roadmap.md` и деталей из `TZ.md`, сгенерировать структурированный Markdown-файл для спринта (например, `sprint1.md`). Этот файл будет содержать декомпозицию высокоуровневых целей на **задачи первого уровня детализации (до "высокой" сложности включительно)**. Каждая такая задача будет описана в соответствии с "Форматом представления задачи". Дальнейшая, более глубокая декомпозиция этих задач (до "средней" сложности для исполнимых подзадач) будет происходить в отдельных файлах `docs/tasks/tasksX/task-X-Y.Z.md` на последующих этапах.

**Примечание:** Общие правила работы с задачами представлены в [отдельном документе](./tasksrules.md).

**Входные данные для ИИ (предоставляются Пользователем при запросе на создание файла спринта):**

1.  **Идентификатор спринта:** Номер спринта из (согласно `Roadmap.md`) (например, "Спринт 1", "Спринт 1.3").
2.  **Краткое описание целей спринта:** Список из 2-5 основных целей/направлений работ на спринт (согласно `Roadmap.md`).
3.  **Доступ к содержимому (или актуальным выдержкам) `TZ.md` и `Roadmap.md`:** Для получения контекста, деталей, требований и критериев приемки воспользуйся этими файлами.
4.  **Расположение файлов:** Все файлы со спринтами создаются в папке `docs/sprints/`, а файлы с детализированными задачами в папке `docs/tasks/tasks<N>/`
5.  **Длительность спринта:** Рекомендуемая продолжительность спринта (обычно 2 недели, но может быть скорректирована в зависимости от объема работ).

## Формат представления задачи в файле `sprint<N>.md`

_(Этот формат будет использоваться для описания каждой отдельной задачи первого уровня детализации внутри файла `sprint<N>.md`)_

- **Название:** Краткое, ясное.
- **Ссылка на дорожную карту:** Якорем, на конкретный раздел в roadmap.md
- **ID Задачи/Якорь:** `task-<X>-<Y>.<Z>` (где `X` – номер спринта (из названия файла, например, `1` для `sprint1.md`); `Y` – номер основной цели спринта из `Roadmap.md` внутри данного спринта, начиная с 1; `Z` – порядковый номер задачи в рамках этой цели, начиная с 1). _Пример: `task-1-1.1` – для Спринта 1, первой цели, первой задачи. Для спринта 1.4 пример: `task-1.4-1.1`_
- **Зависимости:** (опционально) Список ID задач из текущего или предыдущих спринтов (например, `task-1-1.1, task-0.3-2`), которые должны быть выполнены перед началом текущей задачи.
- **Контекст и Цель:** Зачем эта задача? Какую проблему решает? Какова бизнес-цель?
- **Ожидаемый Результат (кратко):** Краткое описание того, что должно быть достигнуто по итогам выполнения этой задачи (более детальные Acceptance Criteria будут в файле `tasksX/task-X-Y.Z.md`).
- **Ссылка на детализацию:** `[Детальное описание и подзадачи](./tasks<X>/task-<X>-<Y>.<Z>.md)` (если задача требует дальнейшей декомпозиции до "средней" сложности; это поле заполняется, когда создается отдельный файл задачи).
- **Оценка Сложности (первичная):** (Высокая, Средняя, Низкая) – _задачи "очень высокой" сложности здесь не допускаются._
- **Тех. Указания (ключевые):** Основные языки, фреймворки, библиотеки, если они критичны для понимания задачи на этом уровне.
- **Нефункциональные Требования (ключевые):** Наиболее важные НФТ, которые нужно учесть.
- **Потенциальные риски:** (опционально) Описание возможных рисков, которые могут повлиять на выполнение задачи.
- **Интеграционные точки:** (опционально) Описание взаимодействий с другими командами или системами для выполнения задачи.
- **Вопросы для Уточнения (первичные):** Ключевые вопросы к Пользователю, если они блокируют понимание задачи на этом уровне.
- **Статус задачи:** `[ ]` _(будет обновляться Пользователем или ИИ по мере выполнения согласно общим правилам)_

**Процесс генерации файла `sprint<N>.md` со стороны ИИ:**

1.  **Создание структуры файла `sprint<N>.md`:**

    - Именование файла: `sprint<Номер_спринта_из_Roadmap>.md`.
    - **Заголовок Первого Уровня (`#`):** Название спринта и его плановые даты.
    - **Ссылка на общие правила:** В начале файла:
      ```markdown
      [Ссылка на общие правила работы с задачами](../tasksrules.md)
      ```
    - **Ссылка на спринт в дорожной карте:** Сразу после ссылки на общие правила добавить:
      ```markdown
      [Ссылка на спринт в дорожной карте](../Roadmap.md#спринт-N)
      ```
      где N - номер спринта. Якорь должен точно соответствовать заголовку спринта в Roadmap.md.
    - **Основные цели спринта (Заголовок Второго Уровня `##`):** Пронумерованный список целей из `Roadmap.md`.
    - **Межспринтовые зависимости (Заголовок Второго Уровня `##`):**
      - **Входящие зависимости:** Задачи из предыдущих спринтов, от которых зависят задачи текущего спринта.
      - **Исходящие зависимости:** Задачи текущего спринта, от которых будут зависеть задачи в будущих спринтах.

2.  **Декомпозиция каждой цели спринта на задачи первого уровня:**

    - Для каждой цели спринта:
      - Анализируются соответствующие разделы в `TZ.md` и `Roadmap.md`.
      - Высокоуровневая цель разбивается на конкретные, измеримые и достижимые задачи **первого уровня детализации**.
      - **Уровень декомпозиции и оценка сложности:**
        - Используется 4 уровня оценки сложности задач: "Очень высокая", "Высокая", "Средняя", "Низкая".
        - При декомпозиции целей спринта для файла `sprint<N>.md`, каждая полученная задача **не должна иметь сложность "Очень высокая"**.
        - Если при первоначальной декомпозиции цели получается задача, которая оценивается как "Очень высокая", она должна быть немедленно разбита на несколько более мелких задач, максимальная сложность которых в файле `sprint<N>.md` будет "Высокая".
        - Задачи, оцененные в `sprint<N>.md` как "Высокая" или "Средняя", **будут далее детализироваться до подзадач с максимальной сложностью "Средняя"** (или "Низкая", когда это правило будет уточнено Пользователем для отдельных файлов задач `tasks<X>/task-<X>-<Y>.<Z>.md`) на следующем этапе работы.
      - Учитываются ключевые нефункциональные требования.

3.  **Форматирование каждой задачи первого уровня (внутри `sprint<N>.md`):**

    - Использовать **"Формат представления задачи в файле `sprint<N>.md`"** (описанный выше).
    - Особое внимание уделить четкому "Названию", "Контексту и Цели" и "Ожидаемому Результату (кратко)".
    - Поле "Ссылка на детализацию" изначально может быть пустым или содержать предполагаемый путь к будущему файлу задачи.

4.  **Структура задач в файле `sprint<N>.md`:**

    - Задачи группируются под соответствующими основными целями спринта.

5.  **Обработка неопределенности и приоритизация:**

    - **Неопределенность:** Если цель из Roadmap слишком абстрактна для декомпозиции даже до задач "высокой" сложности без значительных предположений, первой задачей по такой цели будет "Исследование и детализация требований для [цель спринта]", с последующим созданием файла `tasksX/task-X-1.1.md` для этого исследования.

6.  **Итоговый результат для Пользователя:**

    - Сгенерированный Markdown-текст для файла `sprint<N>.md`.

7.  **Запрос на утверждение Плана Спринта Пользователем:**

    - После генерации файла спринта, он будет представлен Пользователю для утверждения.
    - Обсуждение может быть итеративным до финального согласования плана спринта.

8.  **Секция ретроспективы в конце спринта:**
    - По завершении спринта, в файл добавляется секция "Ретроспектива спринта" (Заголовок Второго Уровня `##`), которая содержит:
      - **Достигнутые результаты:** Краткое описание того, что было достигнуто в рамках спринта.
      - **Незавершенные задачи:** Список задач, которые не были выполнены, с причинами.
      - **Извлеченные уроки:** Что пошло хорошо, что можно улучшить.
      - **Корректировки процесса:** Изменения, которые стоит внести в процесс работы.
      - **Предложения для следующего спринта:** Рекомендации и улучшения для следующей итерации.
