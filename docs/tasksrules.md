# Правила работы с задачами для ИИ ("Партнера программиста")

**Общие принципы:** Этот документ описывает правила взаимодействия между Пользователем и ИИ для эффективной работы над проектом. Он включает общие правила, формат представления задач, а также правила для ИИ по созданию и детализации файлов спринтов и отдельных задач.

---

## Часть 1: Общие правила взаимодействия

1.  **Статус задач:**

    - Выполнено: `[x]`
    - В процессе: `[.]` (Используется ИИ для обозначения работы над многошаговой задачей в рамках текущего ответа)
    - Заблокировано: `[!]` (С указанием причины и ожидаемого действия от Пользователя)

2.  **Утверждение фаз/спринтов/крупных задач:**

    - ИИ запрашивает одобрение у Пользователя перед началом новой крупной фазы/модуля или по завершении всех задач спринта (согласно файлу `sprintN.md`).
    - **Отчет ИИ для одобрения должен включать:**
      - Резюме выполненных работ.
      - Список измененных/созданных файлов (концептуально, с указанием полных путей, например, `tasks1/task11.md`, и предоставлением их содержимого или описания изменений).
      - Предложение по формулировке коммита в стиле Conventional Commits для группы изменений.
      - Подтверждение выполнения Acceptance Criteria (если они были четко определены для завершенных задач).
      - Описание возникших проблем, принятых решений и потенциальных рисков.
    - Утверждение производится **Пользователем** после получения отчета от ИИ.

3.  **Отчет об изменениях, файловая структура и синхронизация с GitHub:**

    - При отчете о выполненных задачах или при утверждении фаз ИИ предоставляет список файлов, которые были бы изменены или созданы, с их полными путями и описанием сути изменений (или предложением для коммита).
    - **Файлы спринтов:** Именуются `sprint<N>.md` (например, `sprint1.md`, `sprint1.3.md` – в соответствии с нумерацией из `Roadmap.md`). Размещаются в папке `docs/sprints/`. Содержат задачи первого уровня детализации.
    - **Папки детализированных задач:** `tasks<N>/` (например, `tasks1/` для задач из `sprint1.md`, `tasks1.3/` для задач из `sprint1.3.md`). Размещаются в папке `docs/tasks/`. **Важно:** Для каждого спринта создается своя отдельная подпапка внутри `docs/tasks/` с названием `tasks[номер спринта]`. Файлы задач должны размещаться строго в соответствующей папке для своего спринта. К примеру, для спринта 1.3 расположение будет `docs/tasks/tasks1.3/`, а для спринта 2 — `docs/tasks/tasks2/`. Смешивание задач разных спринтов в одной папке не допускается.
    - **Файлы детализированных задач:** Именуются `task-<X>-<Y>.<Z>.md` внутри соответствующей папки спринта. `X` – номер спринта, `Y` – номер основной цели спринта из `Roadmap.md`, `Z` – порядковый номер задачи в рамках этой цели. (например, `docs/tasks/tasks1/task-1-1.1.md`). Содержат полную детализацию задачи.
    - **Синхронизация с GitHub (выполняется ИИ):**
      - **Обязательная проверка ИИ:** Перед созданием коммита ИИ должна запустить все настроенные линтеры и автоматические тесты (unit, integration и т.д.), относящиеся к измененному коду и функциональности, предложенной ИИ.
      - **Коммит и Push ИИ:** Коммит создается ИИ только после успешного прохождения всех проверок. Затем ИИ выполняет отправку (push) этих изменений в основной удаленный репозиторий GitHub. ИИ не выполняет эти действия.

4.  **Планирование и выполнение:**

    - ИИ не отмечает будущие задачи выполненными без явного запроса от Пользователя.
    - При предложении плана с отложенными задачами – ИИ явно указывает на это.

5.  **Структура и детализация задач (см. также Часть 3 в [sprintsrules.md](./sprintsrules.md) и Часть 4):**

    - ИИ следует порядку задач, определенному в файлах спринтов (`sprint<N>.md`).
    - При создании новых _крупных_ подзадач/эпиков, ИИ использует "Формат представления задачи" (см. Часть 2 этого документа), ссылаясь на соответствующий файл задачи.
    - _Мелкие_ подзадачи (шаги внутри основной задачи) описываются кратко с чек-боксом `[ ]` непосредственно в файле основной задачи (`task<X><Y>.<Z>.md`). ИИ концептуально отмечает выполнение этих мелких подзадач `[x]`, если они являются частью его ответа, не являются блокирующими или ключевыми и не требуют отдельного утверждения.
    - ИИ стремится к единообразию именования и структуры подзадач.

6.  **Документация и ресурсы:**

    - При необходимости ИИ предоставляет ссылки на релевантную документацию с указанием версий (если это критично и информация доступна).

7.  **Блокировка задач:**

    - При блокировке задачи ИИ указывает причину, зависимости (если есть) и ожидаемое действие от Пользователя для разблокировки.

8.  **Проверка полноты фаз/спринтов:**

    - Перед запросом на переход к следующей фазе/спринту ИИ помогает Пользователю проверить выполнение всех запланированных задач, включая нефункциональные требования (если они были определены).

9.  **Комментарии и обоснования:**

    - Комментарии в коде для сложных или неочевидных участков пишутся ИИ на **русском языке**, если Пользователем не указано иное в стилевых гайдах проекта.
    - ИИ предоставляет обоснование предлагаемых технических решений. Для ключевых решений кратко упоминаются рассмотренные альтернативы (1-2 варианта), если выбор не был абсолютно очевидным.

10. **Обработка ошибок в коде:**

    - ИИ стремится генерировать код с корректной обработкой ошибок, осмысленными сообщениями об ошибках и, по возможности, предлагает пути решения проблем.

11. **Управление зависимостями (для `package.json`, `requirements.txt` и т.п.):**

    - По умолчанию ИИ использует последние стабильные версии с использованием диапазонов (например, `^1.2.3` для `package.json`), чтобы разрешать неломающие обновления.
    - При добавлении новой зависимости ИИ указывает причину ее добавления.
    - Используются стандартные менеджеры зависимостей для соответствующей платформы.

12. **Стиль кода:**

    - ИИ следует общепринятым стандартам стиля для конкретного языка (например, PEP 8 для Python, Google Style Guide для TypeScript/JavaScript) или ориентируется на предоставленный Пользователем файл конфигурации линтера/форматтера (например, `.eslintrc.js`, `.prettierrc.js`).
    - Если стиль неясен, ИИ запросит уточнение или будет использовать стандартные конвенции языка.

13. **Ограничения и предположения ИИ:**

    - ИИ будет стараться явно указывать сделанные им предположения или существующие ограничения своих знаний/возможностей, если это релевантно для выполнения задачи.

14. **Запрос на уточнение:**

    - ИИ не будет приступать к выполнению задачи или ее части при наличии существенных неясностей. Вместо этого он сформулирует конкретные уточняющие вопросы Пользователю.

15. **Проактивные предложения:**
    - Помимо выполнения поставленных задач, ИИ может предлагать улучшения в кодовой базе, архитектуре или рабочем процессе, если видит такую возможность, кратко обосновывая свои предложения.

## Часть 2: Формат представления задачи для ИИ (сжатый)

_(Используется для детализации задач в отдельных файлах `tasks<X>/task<X><Y>.<Z>.md`)_

- **Обязательные указания для ИИ:**

  - В начале каждого файла задачи должна быть ссылка на правила работы с задачами (т.е. на этот документ): `[Правила работы с задачами](../../tasksrules.md)`, обязательная к изучению для ИИ.
  - Каждая задача должна использовать правило: "use context7".

- **Название:** Краткое, ясное (соответствует заголовку в файле задачи).
- **ID Задачи/Путь к файлу:** Например, `tasks1/task-1-1.1.md` (для спринта 1, раздел 1.1) или `tasks1.4/task-1.4-1.1.md` (для спринта 1.4, раздел 1.1).
- **Приоритет/Срочность:** (Высокий, Средний, Низкий)
- **Зависимости:** (опционально) Список ID задач (например, `task-1-1.1, task-1-2.3`), которые должны быть выполнены перед началом текущей задачи.
- **Контекст и Цель:** Зачем? Проблема? Бизнес-цель?
- **Acceptance Criteria / Подзадачи:** Четкие, измеримые критерии (можно в формате BDD: Given-When-Then). Подзадачи с `[ ]` в описании. _(Здесь подзадачи декомпозируются ИИ до максимальной сложности "Средняя", если Пользователем не будет позже указан уровень "Низкая")_.
- **Тех. Указания:** Языки, фреймворки, библиотеки (версии); БД; Архитектура. Версии инструментов (если критично) – ИИ уточняет или предлагает последние стабильные.
- **Нефункциональные Требования:** Производительность, Масштабируемость, Безопасность, Логирование, Usability. При отсутствии четких метрик от Пользователя – ИИ использует лучшие практики или запрашивает уточнение.
- **Итеративность:** Несколько итераций? Промежуточные результаты? Часть спринта?
- **Формат Вывода от ИИ:** Код (предложения по файлам/структуре), ответ в чате, предложение по обновлению кода (с формулировкой коммита).
- **Вопросы для Уточнения:** Вопросы от ИИ к Пользователю для начала или продолжения работы. Но на каждый вопрос, должен быть предварительный ответ от ИИ с точки зренния лучше практики.
- **Безопасность:** (для релевантных задач) Валидация ввода, OWASP Top 10, шифрование, параметризованные запросы и т.д.
- **Документирование Кода:** API (JSDoc/Sphinx/Swagger и т.п.), сложные алгоритмы, README. Формат комментариев – стандартный для языка или по указанию Пользователя. Комментарии в коде пишутся на **русском языке**, если не указано иное.
- **Генерация Тестов:** Типы (unit, integration), ожидаемое покрытие (стремиться к разумному, если не указано), используемый фреймворк (Vitest, PyTest, JUnit и т.д.).
- **Откат/План Б:** (для критических/рискованных задач) Действия при сбое, путь отката, альтернативы. ИИ может рекомендовать определить, если не указано.
- **Измененные файлы (ИИ):** _(Это поле заполняется ИИ при отчете о выполнении задачи, а не при ее постановке)_.

## Часть 3: Правила для ИИ по детализации задач в отдельных файлах

**Цель:** На основе задач первого уровня детализации из файлов спринтов (`sprint<N>.md`), создать отдельные файлы с полным описанием каждой задачи и её декомпозицией до более мелких подзадач (максимальная сложность "Средняя").

**Процесс детализации задач:**

1. **Создание файла задачи:**

   - Для каждой задачи первого уровня из файла спринта создается отдельный файл в соответствующей папке `docs/tasks/tasks<N>/` при необходимости детализации.
   - Имя файла формируется по шаблону: `task-<X>-<Y>.<Z>.md`, где `X` – номер спринта, `Y` – номер основной цели спринта из `Roadmap.md`, `Z` – порядковый номер задачи в рамках этой цели. Например, `task-1-1.1.md` для спринта 1, первой цели, первой задачи или `task-1.4-2.3.md` для спринта 1.4, второй цели, третьей задачи.

2. **Структура файла задачи:**

   - Файл должен содержать полное описание задачи в соответствии с "Форматом представления задачи для ИИ" (см. Часть 2 этого документа).
   - Сложные задачи должны быть декомпозированы на более мелкие подзадачи (шаги) с четкими критериями выполнения.
   - Все подзадачи должны иметь чек-боксы `[ ]` для отслеживания прогресса.

3. **Уровень детализации:**

   - По умолчанию, задачи детализируются до подзадач с максимальной сложностью "Средняя".
   - Если Пользователь указывает на необходимость более детальной декомпозиции, подзадачи могут быть разбиты до сложности "Низкая".

4. **Связь с файлом спринта:**

   - В файле спринта (`sprint<N>.md`) для каждой задачи первого уровня должна быть ссылка на соответствующий файл задачи.
   - При обновлении статуса задачи в файле задачи, соответствующий статус должен быть синхронизирован и в файле спринта.

5. **Обновление и итеративное улучшение:**
   - Файлы задач могут обновляться по мере получения новой информации или уточнений от Пользователя.
   - При значительных изменениях в задаче ИИ должен обновить как файл задачи, так и связанную информацию в файле спринта.
