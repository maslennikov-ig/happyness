# Конфигурация PostgreSQL для проекта Happyness

## Выбор версии PostgreSQL

Для проекта Happyness была выбрана **PostgreSQL 17.5** по следующим причинам:

1. **Стабильность и производительность**:
   - PostgreSQL 17.x является последней стабильной версией с улучшенной производительностью и оптимизацией запросов
   - Включает улучшенные алгоритмы индексирования, что важно для быстрого поиска и фильтрации данных

2. **Совместимость с Prisma ORM**:
   - Полная поддержка всех функций Prisma ORM, включая миграции и типы данных
   - Оптимальная работа с UUID и JSON-полями, которые используются в проекте

3. **Расширенные возможности для бизнес-логики**:
   - Поддержка сложных типов данных (массивы, JSON, JSONB)
   - Расширенная поддержка полнотекстового поиска с помощью tsvector/tsquery
   - Поддержка транзакций и ACID-совместимость для обеспечения целостности данных

4. **Безопасность**:
   - Улучшенные механизмы аутентификации и авторизации
   - Шифрование данных на уровне строк
   - Поддержка SSL-соединений

## Оптимальные настройки для разработки

### Основные настройки

```
listen_addresses = '*'
port = 5432
max_connections = 100
```

**Обоснование**: Стандартный порт и достаточное количество соединений для разработки. Разрешаем подключение со всех адресов для удобства разработки.

### Память

```
shared_buffers = 128MB
work_mem = 8MB
maintenance_work_mem = 64MB
```

**Обоснование**: Для среды разработки выделяем умеренное количество памяти. В production эти значения будут увеличены в зависимости от доступных ресурсов сервера.

### Журналирование

```
log_min_duration_statement = 250ms
log_checkpoints = on
log_connections = on
log_disconnections = on
log_lock_waits = on
```

**Обоснование**: Расширенное логирование для отладки производительности и выявления проблем. Логируем запросы, выполняющиеся дольше 250мс, для выявления медленных операций.

### Настройки WAL (Write-Ahead Log)

```
wal_level = replica
max_wal_size = 1GB
min_wal_size = 80MB
```

**Обоснование**: Настройка уровня WAL для возможности репликации в будущем. Оптимальные размеры для среды разработки.

### Планировщик запросов

```
random_page_cost = 1.1
effective_cache_size = 512MB
```

**Обоснование**: Оптимизация для SSD-дисков, которые используются в среде разработки. Значение random_page_cost близкое к 1.0 указывает PostgreSQL, что случайное чтение почти так же быстро, как последовательное (характерно для SSD).

### Автоочистка

```
autovacuum = on
autovacuum_max_workers = 3
autovacuum_naptime = 1min
```

**Обоснование**: Включаем автоочистку для поддержания производительности базы данных. Устанавливаем частые проверки (1 минута) для быстрого реагирования на изменения в данных.

### Настройки для разработки

```
synchronous_commit = off
full_page_writes = off
```

**Обоснование**: В среде разработки отключаем некоторые механизмы безопасности для повышения производительности. В production эти настройки будут включены для обеспечения целостности данных.

## Резервное копирование

Для проекта настроено автоматическое резервное копирование базы данных с помощью скриптов:

1. **backup.sh** - создает резервные копии базы данных в формате custom (PostgreSQL)
2. **restore.sh** - восстанавливает базу данных из резервной копии

**Стратегия резервного копирования**:
- Ежедневное создание полной резервной копии
- Хранение резервных копий за последние 7 дней
- Автоматическое удаление устаревших резервных копий

## Заключение

Выбранная конфигурация PostgreSQL оптимизирована для среды разработки проекта Happyness. Она обеспечивает хороший баланс между производительностью и удобством отладки. При переходе в production-среду параметры будут скорректированы с учетом доступных ресурсов сервера и требований к безопасности данных.
