# Конфигурация Redis для проекта Happyness

## Выбор версии Redis

Для проекта Happyness была выбрана **Redis 8.0.1** по следующим причинам:

1. **Производительность и стабильность**:
   - Redis 8.0.x является последней стабильной версией с улучшенной производительностью
   - Включает оптимизации для работы с большими наборами данных
   - Улучшенное управление памятью и сниженное потребление ресурсов

2. **Новые возможности**:
   - Поддержка функций (Redis Functions) для выполнения пользовательских скриптов
   - Улучшенная поддержка JSON для хранения структурированных данных
   - Расширенные возможности для работы с временными рядами данных

3. **Безопасность**:
   - Улучшенная система аутентификации и авторизации
   - Поддержка шифрования данных в состоянии покоя (encryption at rest)
   - Расширенные возможности для защиты от атак

## Оптимальные настройки для кеширования

### Основные настройки

```
bind 0.0.0.0
protected-mode yes
port 6379
```

**Обоснование**: Стандартный порт и разрешение подключений со всех адресов для удобства разработки. Protected mode включен для базовой защиты.

### Настройки памяти

```
maxmemory 256MB
maxmemory-policy allkeys-lru
```

**Обоснование**: 
- Ограничение памяти в 256MB достаточно для среды разработки и кеширования основных данных
- Политика LRU (Least Recently Used) обеспечивает автоматическое удаление наименее используемых ключей при достижении лимита памяти
- Для production-среды это значение будет увеличено в зависимости от нагрузки и доступных ресурсов

### Настройки персистентности

```
save 900 1
save 300 10
save 60 10000
```

**Обоснование**:
- Сохранение данных на диск происходит при следующих условиях:
  - Каждые 15 минут, если изменился хотя бы 1 ключ
  - Каждые 5 минут, если изменились хотя бы 10 ключей
  - Каждую минуту, если изменились хотя бы 10000 ключей
- Такая конфигурация обеспечивает баланс между сохранностью данных и производительностью

### Настройки для разработки

```
appendonly no
```

**Обоснование**: В среде разработки отключаем режим Append-Only File (AOF) для повышения производительности. В production-среде этот параметр будет включен для обеспечения надежности данных.

## Сценарии использования Redis в проекте

Redis будет использоваться для следующих целей:

1. **Кеширование данных**:
   - Кеширование результатов запросов к базе данных
   - Кеширование часто запрашиваемых данных (пользовательские профили, настройки)
   - Кеширование результатов API-запросов к внешним сервисам

2. **Управление сессиями**:
   - Хранение информации о сессиях пользователей
   - Быстрый доступ к данным аутентификации

3. **Ограничение частоты запросов (Rate Limiting)**:
   - Защита API от злоупотреблений
   - Контроль количества запросов от каждого клиента

4. **Очереди задач**:
   - Хранение и обработка асинхронных задач (например, отправка email-уведомлений)
   - Распределение нагрузки между воркерами

## Управление Redis

Для удобства управления Redis созданы следующие скрипты:

1. **Очистка кеша**:
   - Скрипт для выборочной очистки кеша по паттернам ключей
   - Возможность полной очистки кеша при необходимости

2. **Мониторинг**:
   - Скрипт для отслеживания использования памяти
   - Мониторинг производительности и количества операций

## Заключение

Выбранная конфигурация Redis оптимизирована для среды разработки проекта Happyness. Она обеспечивает эффективное кеширование данных и управление сессиями. При переходе в production-среду параметры будут скорректированы с учетом доступных ресурсов сервера и требований к безопасности данных.
