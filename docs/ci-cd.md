# CI/CD Конфигурация

Этот документ описывает настройку CI/CD (Continuous Integration/Continuous Deployment) для проекта Happyness.

## Используемые технологии

- **GitHub Actions** - платформа для автоматизации рабочих процессов
- **Husky** - инструмент для настройки Git-хуков
- **lint-staged** - инструмент для запуска линтеров на staged файлах
- **ESLint** - статический анализатор кода для JavaScript/TypeScript
- **Prettier** - инструмент для форматирования кода

## Рабочие процессы GitHub Actions

### 1. Pull Request Checks (`pr-checks.yml`)

Запускается при создании или обновлении Pull Request в ветки `main`.

**Этапы:**
- **validate** - проверка кода:
  - Установка зависимостей
  - Линтинг кода (ESLint)
  - Проверка типов TypeScript
  - Запуск тестов
  - Сборка проекта

- **security-scan** - проверка безопасности:
  - Аудит зависимостей npm

### 2. Main Build (`main-build.yml`)

Запускается при пуше в ветку `main`.

**Этапы:**
- Установка зависимостей с кэшированием
- Линтинг кода
- Сборка проекта
- Запуск тестов
- Деплой (заглушка, будет настроен позже)

## Локальные проверки

### Git-хуки (Husky)

В проекте настроены следующие Git-хуки:

- **pre-commit** - запускает lint-staged для проверки и форматирования staged файлов перед коммитом

### lint-staged

Конфигурация в файле `.lintstagedrc`:

- **JavaScript/TypeScript файлы (*.js, *.jsx, *.ts, *.tsx)**:
  - ESLint с автоисправлением
  - Prettier для форматирования

- **JSON, Markdown, YAML файлы (*.json, *.md, *.yml, *.yaml)**:
  - Prettier для форматирования

- **CSS файлы (*.css)**:
  - Prettier для форматирования

## Настройка проекта

1. **Установка зависимостей:**
   ```bash
   npm install
   ```

2. **Инициализация Husky:**
   ```bash
   npm run prepare
   ```

3. **Запуск линтера:**
   ```bash
   npm run lint
   ```

4. **Запуск линтера с автоисправлением:**
   ```bash
   npm run lint:fix
   ```

5. **Проверка типов TypeScript:**
   ```bash
   npm run type-check
   ```

## Рекомендации по работе с CI/CD

1. **Перед созданием Pull Request:**
   - Запустите `npm run lint:fix` для исправления стилистических ошибок
   - Запустите `npm run type-check` для проверки типов
   - Запустите `npm test` для запуска тестов

2. **При работе с ветками:**
   - Создавайте ветки от актуальной `main`
   - Используйте префиксы для веток: `feature/`, `bugfix/`, `hotfix/`
   - Делайте регулярные коммиты с понятными сообщениями

3. **Для CI/CD:**
   - Следите за результатами проверок в GitHub Actions
   - Исправляйте ошибки до мержа Pull Request
   - При необходимости обновляйте конфигурацию CI/CD в файлах `.github/workflows/`
