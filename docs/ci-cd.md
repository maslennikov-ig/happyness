## CI (Continuous Integration)

В проекте настроены следующие рабочие процессы CI:

### Основной процесс CI

Файл: `.github/workflows/ci.yml`

Пайплайн CI запускается при каждом пуше в ветки `main` и `develop`, а также при создании пулл-реквестов в эти ветки.

### Задачи CI:

1. **Lint**: Проверка кода с помощью ESLint и проверка типов TypeScript.

> **Важно:** Frontend разворачивается только локально (npm run dev), в Docker Compose остаются только backend, postgres, redis, adminer (опционально). Для работы фронта укажите NEXT_PUBLIC_API_URL, который указывает на backend в докере (например, http://localhost:4000/api).

- Шаги:
  - Установка зависимостей
  - Запуск ESLint
  - Проверка типов TypeScript

2. **Test**: Запуск автоматических тестов.
   - Шаги:
     - Установка зависимостей
     - Генерация Prisma клиента
     - Запуск тестов фронтенда
     - Запуск тестов бэкенда
     - Подробнее о тестах см. [Руководство по тестированию](./test-guide.md)

### Проверка структуры проекта

Файл: `.github/workflows/check-project-structure.yml`

Пайплайн проверки структуры проекта запускается при каждом пуше в ветки `main` и `develop`, а также при создании пулл-реквестов в эти ветки.

#### Задачи проверки структуры проекта:

1. **Проверка структуры проекта**: Выявление отклонений от стандартов структуры.
   - Шаги:
     - Установка зависимостей
     - Установка дополнительных зависимостей для отчетов
     - Проверка структуры проекта
     - Генерация отчета о структуре проекта
     - Загрузка отчета о структуре проекта
     - Создание issue при обнаружении проблем

### Проверка качества проекта

Файл: `.github/workflows/project-quality.yml`

Пайплайн проверки качества проекта запускается при каждом пуше в ветки `main` и `develop`, а также при создании пулл-реквестов в эти ветки.

#### Задачи проверки качества проекта:

1. **Проверка структуры проекта**: Выявление отклонений от стандартов структуры.

   - Шаги:
     - Установка зависимостей
     - Проверка структуры проекта
     - Генерация отчета о структуре проекта

2. **Проверка зависимостей**: Анализ и оптимизация зависимостей проекта.

   - Шаги:
     - Установка зависимостей
     - Установка дополнительных зависимостей для отчетов
     - Анализ зависимостей
     - Загрузка отчета о зависимостях

3. **Проверка покрытия кода тестами**: Проверка покрытия кода тестами с заданным пороговым значением.

   - Шаги:
     - Установка зависимостей
     - Генерация Prisma клиента
     - Запуск тестов с покрытием
     - Проверка пороговых значений покрытия
     - Загрузка отчетов о покрытии

4. **Проверка документации API**: Валидация и генерация документации API.

   - Шаги:
     - Установка зависимостей
     - Установка Swagger CLI
     - Валидация Swagger/OpenAPI документации
     - Генерация HTML документации
     - Загрузка API документации

5. **Создание issue при обнаружении проблем**: Автоматическое создание issue при обнаружении проблем в проекте.
   - Шаги:
     - Создание issue для проблем с качеством проекта

## CD (Continuous Deployment)

Файл: `.github/workflows/cd.yml`

Пайплайн CD запускается при каждом пуше в ветку `main`.

### Задачи CD:

1. **Build and Deploy**: Сборка и деплой приложения.
   - Шаги:
     - Установка зависимостей
     - Генерация Prisma клиента
     - Сборка приложения
     - Запуск тестов
     - Подготовка пакета для деплоя
     - Деплой на продакшн сервер (имитация)

## Docker Build and Push

Файл: `.github/workflows/docker-build.yml`

Пайплайн сборки и публикации Docker образа запускается при каждом пуше в ветку `main` и при создании тега с префиксом `v`.

### Задачи Docker Build:

1. **Build and Push Docker image**: Сборка и публикация Docker образа в GitHub Container Registry.
   - Шаги:
     - Настройка Docker Buildx
     - Авторизация в GitHub Container Registry
     - Извлечение метаданных для Docker
     - Сборка и публикация Docker образа

## Структура Docker

### Dockerfile

Многоэтапная сборка для оптимизации размера образа:

1. **base**: Базовый образ Node.js Alpine
2. **deps**: Установка зависимостей
3. **builder**: Сборка приложения
4. **runner**: Финальный образ для запуска приложения

### .dockerignore

Файл `.dockerignore` исключает ненужные файлы при сборке Docker образа, что уменьшает размер контекста сборки и самого образа.

## Запуск и деплой

### Локальный запуск

```bash
# Запуск в режиме разработки
npm run dev

# Сборка и запуск в режиме production
npm run build
npm start
```

> **Важно:** основной порт фронтенда теперь 3100 (ранее был 3000).

### Запуск с использованием Docker

```bash
# Сборка образа
docker build -t happyness .

# Запуск контейнера
docker run -p 3100:3100 -p 3001:3001 happyness
```

### Запуск с использованием Docker Compose

```bash
# Запуск всех сервисов
docker-compose up -d

# Остановка всех сервисов
docker-compose down
```

## Настройка CI/CD для различных окружений

На текущем этапе проект поддерживает два основных окружения:

- **Development (dev)**: для локальной разработки
- **Production (prod)**: для рабочего окружения

Мы используем различные конфигурации и переменные окружения для каждого из них, что позволяет разработчикам эффективно тестировать функциональность перед выпуском в production.
