# Задача 1.3.4: Разработка регистрации и профилей пользователей

[Правила работы с задачами](../../tasksrules.md)

use context7

## Описание задачи

**ID Задачи/Путь к файлу:** [tasks1.3/task-1.3-2.2.md](../../sprints/sprint1.3.md#задача-22-разработка-регистрации-и-профилей-пользователей)

**Приоритет/Срочность:** Средний

**Зависимости:** task13.3 (Реализация JWT-токенов для аутентификации)

**Контекст и Цель:** Необходимо реализовать процесс регистрации пользователей различных ролей (Предприниматель, Сотрудник Компании) и создания/редактирования профилей. Важно обеспечить безопасную обработку данных пользователей, включая валидацию и защиту от типовых атак. Функциональность должна учитывать различные типы пользователей и бизнес-требования, связанные с управлением профилями.

## Acceptance Criteria / Подзадачи

1. [ ] Разработать API для регистрации разных типов пользователей

   - [ ] Создать эндпоинт регистрации предпринимателя с необходимыми полями
   - [ ] Создать эндпоинт регистрации сотрудника компании с проверкой приглашения
   - [ ] Реализовать валидацию данных регистрации (email, пароль, персональные данные)
   - [ ] Создать механизм проверки уникальности email
   - [ ] Реализовать процесс подтверждения email при регистрации

2. [ ] Создать модели и репозитории для работы с профилями пользователей

   - [ ] Разработать модель профиля предпринимателя
   - [ ] Разработать модель профиля сотрудника компании
   - [ ] Создать репозитории для доступа к профилям
   - [ ] Реализовать взаимосвязи между профилями и базовыми пользователями
   - [ ] Внедрить механизм миграций для обновления структуры БД

3. [ ] Разработать API для управления профилями

   - [ ] Создать эндпоинты для получения профиля пользователя
   - [ ] Реализовать эндпоинты обновления профиля
   - [ ] Добавить управление настройками приватности данных
   - [ ] Создать функциональность для деактивации/активации профиля
   - [ ] Реализовать механизм управления дополнительными атрибутами профиля

4. [ ] Реализовать функциональность загрузки и управления аватарами

   - [ ] Создать эндпоинты загрузки изображений
   - [ ] Настроить валидацию и оптимизацию изображений
   - [ ] Реализовать хранение и кэширование изображений
   - [ ] Добавить функциональность получения аватара с разными размерами
   - [ ] Обеспечить безопасную обработку файлов

5. [ ] Разработать механизм подтверждения и верификации данных

   - [ ] Разработать процесс верификации email через отправку письма
   - [ ] Создать механизм подтверждения изменений в профиле
   - [ ] Реализовать API для повторной отправки подтверждений
   - [ ] Обеспечить безопасное хранение токенов подтверждения
   - [ ] Добавить возможность аудита изменений профиля

6. [ ] Внедрить безопасное хранение и обработку персональных данных
   - [ ] Реализовать шифрование чувствительных данных в БД
   - [ ] Создать механизмы анонимизации данных для аналитики
   - [ ] Реализовать журналирование доступа к персональным данным
   - [ ] Добавить функциональность экспорта персональных данных пользователя
   - [ ] Обеспечить соответствие требованиям ФЗ-152 "О персональных данных"

## Тех. Указания

- **Языки и фреймворки:** Node.js 22.x, NestJS 11.x, TypeScript 5.x
- **Библиотеки:**
  - class-validator для валидации входящих данных
  - multer для обработки загрузки файлов
  - sharp для обработки изображений
  - nodemailer для отправки email-уведомлений
- **БД и хранение данных:**
  - PostgreSQL (через Prisma) для хранения пользователей и профилей
  - Хранилище для файлов (локальное или S3-совместимое)
- **Архитектурные принципы:**
  - Организация кода согласно [tasks/tasks1/task21_project_structure.md](../../tasks1/task21_project_structure.md)
  - Использование репозиториев для работы с данными
  - Отделение бизнес-логики от контроллеров
  - Применение принципов чистой архитектуры

## Нефункциональные Требования

- **Безопасность:**

  - Защита от атак: XSS, CSRF, инъекции, загрузка вредоносных файлов
  - Соответствие ФЗ-152 "О персональных данных"
  - Безопасное хранение чувствительных данных
  - Механизмы защиты от подбора email при регистрации

- **Производительность:**

  - Оптимизация запросов к БД для быстрой загрузки профилей
  - Эффективная обработка изображений без блокировки основного потока
  - Кэширование часто используемых данных профиля
  - Постраничное получение данных для списков пользователей

- **Масштабируемость:**

  - Разделение хранения данных профиля и файлов (изображений)
  - Возможность горизонтального масштабирования для обработки большого количества запросов
  - Оптимизация хранения и получения аватаров

- **Usability (UX):**

  - Понятные и информативные сообщения об ошибках
  - Интуитивный процесс регистрации с минимальным количеством шагов
  - Гибкие возможности управления профилем
  - Предоставление превью аватаров разных размеров

- **Локализация:**
  - Поддержка разных языков для сообщений об ошибках
  - Корректная обработка языкозависимых данных (имена, адреса)
  - Формат дат в соответствии с локалью пользователя

## Интеграционные точки

- Сервис нотификаций для уведомлений о действиях с профилем

## Вопросы для Уточнения

1. Какие дополнительные поля требуются для профилей разных типов пользователей?

   - Предварительный ответ: Для предпринимателей рекомендуется хранить информацию о компании, сферах деятельности и бизнес-контактах. Для сотрудников компаний важно хранить данные о должности, отделе, контактную информацию для внутренних коммуникаций.

2. Как должен происходить процесс приглашения сотрудников в компанию?

   - Предварительный ответ: Предприниматель (владелец компании) может генерировать уникальные приглашения с ограниченным сроком действия. Сотрудник получает приглашение по email и использует его при регистрации для привязки к компании.

3. Какие требования к обработке и хранению аватаров?
   - Предварительный ответ: Аватары должны храниться в отдельном хранилище, оптимизироваться при загрузке (сжатие, изменение размера), генерироваться в нескольких размерах (thumbnail, средний, полный). Исходные изображения сохраняются для возможности повторной обработки.

## Безопасность

- Валидация всех пользовательских входных данных на стороне сервера
- Ограничение количества попыток регистрации с одного IP-адреса
- Защита от подделки запросов (CSRF-токены)
- Проверка загружаемых файлов на безопасность (тип, размер, содержимое)
- Шифрование чувствительных персональных данных в БД
- Разграничение доступа к API в соответствии с ролями
- Журналирование действий с личными данными для аудита

## Откат/План Б

В случае проблем с производительностью или сложностями реализации:

- Упростить структуру профилей, оставив только базовые необходимые поля
- Временно отказаться от шифрования данных в пользу базовой безопасности
- Использовать локальное хранилище для аватаров вместо внешних сервисов
- Отложить реализацию сложных функций (экспорт данных, аудит) на последующие спринты
