# Задача 1.4: Настройка базы данных

## Правила работы с задачами
* **Отслеживание выполнения:** Выполненные задачи или подзадачи отмечаются как `[x]`.
* **Утверждение фаз:** Перед началом следующей крупной фазы разработки или модуля запрашивайте одобрение пользователя (руководителя проекта).
* **Задачи для пользователя-разработчика:** Если возникают задачи, требующие выполнения человеком-разработчиком, четко формулируйте задачу в чате и ожидайте подтверждения ее выполнения.
* **Отчет об изменениях:** Рядом с выполненной задачей указывайте список созданных или измененных файлов.
* **Планирование:** Не отмечайте будущие задачи как выполненные до получения явного запроса на их реализацию.
* **Структура и порядок:** Следуйте порядку задач, сгруппированных по спринтам. При генерации новых подзадач используйте единообразное именование и структуру.
* **Документация и ресурсы:** При необходимости добавляйте ссылки на релевантную документацию.
* **Блокировка задач:** Если задача заблокирована, четко указывайте причину и зависимости.
* **Проверка фаз:** Перед запросом на переход к следующей фазе убедитесь в полноте выполнения всех задач текущей фазы.
* **Комментарии и обоснования:** Используйте комментарии в коде для сложных участков и предоставляйте обоснования выбранных решений.

## Содержание задачи
- [ ] Настроить PostgreSQL для локальной разработки (Сложность: Средняя)
  - **Вход:** Технические требования к базе данных
  - **Выход:** Работающий экземпляр PostgreSQL с базовой конфигурацией
  
  ##### Подзадачи:
  - [ ] Определить оптимальную версию PostgreSQL и конфигурацию (Сложность: Низкая)
    - **Вход:** Требования к БД из ТЗ
    - **Выход:** Документ с обоснованием выбора версии и настроек PostgreSQL

  - [ ] Настроить конфигурацию PostgreSQL для разработки (Сложность: Средняя)
    - **Вход:** Выбранная версия и требования к производительности
    - **Выход:** Конфигурационный файл postgresql.conf с оптимальными настройками

  - [ ] Настроить процедуры резервного копирования для разработки (Сложность: Низкая)
    - **Вход:** Требования к сохранности данных
    - **Выход:** Скрипты для создания и восстановления резервных копий

- [ ] Настроить базовую Prisma-схему в соответствии с начальным дизайном модели данных (Сложность: Средняя)
  - **Вход:** Модель данных из ТЗ (Раздел 6)
  - **Выход:** Начальная schema.prisma с базовыми сущностями (User, Company)
  
  ##### Подзадачи:
  - [ ] Спроектировать базовые сущности Prisma (User, Company) (Сложность: Средняя)
    - **Вход:** Модель данных из ТЗ для пользователя и компании
    - **Выход:** Определения сущностей User и Company в schema.prisma

  - [ ] Определить связи между базовыми сущностями (Сложность: Низкая)
    - **Вход:** Отношения между сущностями из ТЗ
    - **Выход:** Правильно определенные отношения в schema.prisma

  - [ ] Создать начальные Prisma-миграции (Сложность: Низкая)
    - **Вход:** Разработанная схема Prisma
    - **Выход:** Миграционные файлы для создания начальной структуры БД

- [ ] Настроить Redis для кеширования (Сложность: Средняя)
  - **Вход:** Требования к системе кеширования
  - **Выход:** Настроенный Redis-сервер, интегрированный с Docker Compose
  
  ##### Подзадачи:
  - [ ] Исследовать требования к кешированию и выбрать оптимальную конфигурацию Redis (Сложность: Низкая)
    - **Вход:** Требования к кешированию из ТЗ
    - **Выход:** Документ с обоснованием конфигурации Redis

  - [ ] Настроить Redis в Docker Compose с постоянным хранилищем (Сложность: Средняя)
    - **Вход:** Выбранная конфигурация Redis
    - **Выход:** Настройка Redis в docker-compose.yml с volume для данных

  - [ ] Создать базовые скрипты для управления Redis (очистка, мониторинг) (Сложность: Низкая)
    - **Вход:** Требования к управлению кешем
    - **Выход:** Скрипты для обслуживания Redis-сервера
