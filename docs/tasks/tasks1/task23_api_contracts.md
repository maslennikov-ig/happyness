# Документация по API-контрактам системы Happyness

## Введение

Данный документ описывает API-контракты системы Happyness, включая структуру API, стратегию версионирования, стандарты именования эндпоинтов, форматы ответов и обработку ошибок.

API системы Happyness построено на принципах REST и обеспечивает единообразный, предсказуемый и удобный в использовании интерфейс для взаимодействия с системой.

## Стратегия версионирования API

Подробная информация о стратегии версионирования API представлена в документе [task23_api_versioning.md](./task23_api_versioning.md).

### Краткий обзор

### Ключевые аспекты версионирования

- **URL-версионирование**: `/v1/users`, `/v2/users`
- **Семантическое версионирование**: Основные версии (v1, v2) для несовместимых изменений API
- **Жизненный цикл версий**: Каждая версия API поддерживается минимум 12 месяцев после выпуска следующей версии
- **Структура URL**: `https://api.happyness.com/v{version}/{resource}/{resourceId}/{subresource}`

## Структура эндпоинтов для ключевых сущностей

Подробная информация о структуре эндпоинтов для ключевых сущностей представлена в документе [task23_endpoints.md](./task23_endpoints.md).

1. **Пользователи (Users)**: Управление пользователями системы
2. **Подрядчики (Contractors)**: Управление профилями подрядчиков
3. **Проекты (Projects)**: Управление проектами
4. **Запросы (Requests)**: Управление запросами на услуги
5. **Аутентификация (Auth)**: Аутентификация и авторизация пользователей
6. **Коммуникации (Communications)**: Обмен сообщениями между пользователями

Подробная информация о структуре эндпоинтов для каждой сущности доступна в [документе по структуре эндпоинтов](./task23_endpoints.md).

### Пример структуры эндпоинтов для сущности "Пользователи"

| Метод  | Путь       | Описание                                  | Права доступа        |
| ------ | ---------- | ----------------------------------------- | -------------------- |
| GET    | /users     | Получение списка пользователей            | ADMIN                |
| GET    | /users/:id | Получение данных конкретного пользователя | ADMIN, SELF          |
| POST   | /users     | Создание нового пользователя              | PUBLIC (регистрация) |
| PUT    | /users/:id | Обновление данных пользователя            | ADMIN, SELF          |
| DELETE | /users/:id | Деактивация пользователя                  | ADMIN, SELF          |

## Стандарты именования эндпоинтов

Подробная информация о стандартах именования эндпоинтов представлена в документе [task23_naming_standards.md](./task23_naming_standards.md).

### Краткий обзор

### Ключевые принципы именования

1. **Ресурсно-ориентированный подход**: API строится вокруг ресурсов, а не действий
2. **Использование существительных во множественном числе**: для именования ресурсов
3. **Иерархическая структура**: для представления отношений между ресурсами
4. **Последовательность**: единообразие в именовании и структуре по всему API
5. **Простота и интуитивность**: понятные и предсказуемые имена ресурсов и эндпоинтов

### Примеры правильного именования

```
GET    /users                   # Получение списка пользователей
GET    /users/:userId           # Получение конкретного пользователя
POST   /users                   # Создание пользователя
PUT    /users/:userId           # Обновление пользователя
DELETE /users/:userId           # Удаление пользователя

GET    /projects/:projectId/requests        # Получение запросов проекта
POST   /projects/:projectId/requests        # Создание запроса в проекте
```
