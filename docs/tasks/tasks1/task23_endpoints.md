# Структура эндпоинтов API для ключевых сущностей

В данном документе описывается структура эндпоинтов RESTful API для ключевых сущностей системы Happyness. Все эндпоинты следуют стандартам REST и используют стратегию версионирования, описанную в [документе по версионированию API](./task23_api_versioning.md).

## Общая структура API

Все эндпоинты API доступны по базовому URL:

```
https://api.happyness.com/v1/
```

## 1. Управление пользователями (Users)

### Эндпоинты

| Метод  | Путь               | Описание                                  | Права доступа        |
| ------ | ------------------ | ----------------------------------------- | -------------------- |
| GET    | /users             | Получение списка пользователей            | ADMIN                |
| GET    | /users/:id         | Получение данных конкретного пользователя | ADMIN, SELF          |
| POST   | /users             | Создание нового пользователя              | PUBLIC (регистрация) |
| PUT    | /users/:id         | Обновление данных пользователя            | ADMIN, SELF          |
| DELETE | /users/:id         | Деактивация пользователя                  | ADMIN, SELF          |
| GET    | /users/me          | Получение данных текущего пользователя    | AUTHENTICATED        |
| PUT    | /users/me/password | Изменение пароля                          | AUTHENTICATED        |

### Параметры запросов

#### GET /users

- `page`: номер страницы (по умолчанию 1)
- `limit`: количество элементов на странице (по умолчанию 20, максимум 100)
- `role`: фильтр по роли пользователя (опционально)
- `search`: поиск по имени или email (опционально)

#### POST /users

```json
{
  "email": "user@example.com",
  "password": "securePassword123",
  "name": "John Doe",
  "role": "ENTREPRENEUR"
}
```

## 2. Управление подрядчиками (Contractors)

### Эндпоинты

| Метод  | Путь                    | Описание                                | Права доступа |
| ------ | ----------------------- | --------------------------------------- | ------------- |
| GET    | /contractors            | Получение списка подрядчиков            | AUTHENTICATED |
| GET    | /contractors/:id        | Получение данных конкретного подрядчика | AUTHENTICATED |
| POST   | /contractors            | Регистрация в качестве подрядчика       | ENTREPRENEUR  |
| PUT    | /contractors/:id        | Обновление данных подрядчика            | ADMIN, SELF   |
| DELETE | /contractors/:id        | Удаление профиля подрядчика             | ADMIN, SELF   |
| GET    | /contractors/search     | Поиск подрядчиков по критериям          | AUTHENTICATED |
| PUT    | /contractors/:id/verify | Верификация подрядчика                  | ADMIN         |

### Параметры запросов

#### GET /contractors

- `page`: номер страницы (по умолчанию 1)
- `limit`: количество элементов на странице (по умолчанию 20, максимум 100)
- `verified`: фильтр по статусу верификации (опционально)
- `services`: фильтр по предоставляемым услугам (опционально, через запятую)
- `rating`: минимальный рейтинг (опционально)

#### GET /contractors/search

- `query`: поисковый запрос
- `services`: фильтр по предоставляемым услугам (через запятую)
- `location`: фильтр по местоположению
- `rating`: минимальный рейтинг

## 3. Управление проектами (Projects)

### Эндпоинты

| Метод  | Путь                      | Описание                             | Права доступа  |
| ------ | ------------------------- | ------------------------------------ | -------------- |
| GET    | /projects                 | Получение списка проектов            | AUTHENTICATED  |
| GET    | /projects/:id             | Получение данных конкретного проекта | PROJECT_MEMBER |
| POST   | /projects                 | Создание нового проекта              | ENTREPRENEUR   |
| PUT    | /projects/:id             | Обновление данных проекта            | PROJECT_OWNER  |
| DELETE | /projects/:id             | Удаление проекта                     | PROJECT_OWNER  |
| GET    | /users/:id/projects       | Получение проектов пользователя      | ADMIN, SELF    |
| PUT    | /projects/:id/status      | Изменение статуса проекта            | PROJECT_OWNER  |
| POST   | /projects/:id/contractors | Добавление подрядчика к проекту      | PROJECT_OWNER  |

### Параметры запросов

#### GET /projects

- `page`: номер страницы (по умолчанию 1)
- `limit`: количество элементов на странице (по умолчанию 20, максимум 100)
- `status`: фильтр по статусу проекта (опционально)
- `search`: поиск по названию или описанию (опционально)

#### POST /projects

```json
{
  "title": "Новый веб-сайт",
  "description": "Разработка корпоративного веб-сайта",
  "budget": 50000,
  "startDate": "2025-06-01T00:00:00Z",
  "endDate": "2025-07-15T00:00:00Z"
}
```

## 4. Управление запросами (Requests)

### Эндпоинты

| Метод  | Путь                      | Описание                             | Права доступа       |
| ------ | ------------------------- | ------------------------------------ | ------------------- |
| GET    | /requests                 | Получение списка запросов            | AUTHENTICATED       |
| GET    | /requests/:id             | Получение данных конкретного запроса | REQUEST_PARTICIPANT |
| POST   | /requests                 | Создание нового запроса              | ENTREPRENEUR        |
| PUT    | /requests/:id             | Обновление данных запроса            | REQUEST_OWNER       |
| DELETE | /requests/:id             | Удаление запроса                     | REQUEST_OWNER       |
| GET    | /projects/:id/requests    | Получение запросов проекта           | PROJECT_MEMBER      |
| PUT    | /requests/:id/status      | Изменение статуса запроса            | REQUEST_PARTICIPANT |
| POST   | /requests/:id/contractors | Назначение подрядчика на запрос      | REQUEST_OWNER       |

### Параметры запросов

#### GET /requests

- `page`: номер страницы (по умолчанию 1)
- `limit`: количество элементов на странице (по умолчанию 20, максимум 100)
- `status`: фильтр по статусу запроса (опционально)
- `project`: фильтр по ID проекта (опционально)
- `search`: поиск по названию или описанию (опционально)

#### POST /requests

```json
{
  "title": "Дизайн логотипа",
  "description": "Разработка логотипа для компании",
  "budget": 15000,
  "deadline": "2025-06-15T00:00:00Z",
  "projectId": "project-uuid" // опционально
}
```

## 5. Аутентификация и авторизация (Auth)

### Эндпоинты

| Метод | Путь                 | Описание                        | Права доступа             |
| ----- | -------------------- | ------------------------------- | ------------------------- |
| POST  | /auth/login          | Аутентификация пользователя     | PUBLIC                    |
| POST  | /auth/register       | Регистрация нового пользователя | PUBLIC                    |
| POST  | /auth/refresh        | Обновление токена доступа       | PUBLIC (с refresh token)  |
| POST  | /auth/logout         | Выход из системы                | AUTHENTICATED             |
| POST  | /auth/password/reset | Запрос на сброс пароля          | PUBLIC                    |
| PUT   | /auth/password/reset | Установка нового пароля         | PUBLIC (с токеном сброса) |

### Параметры запросов

#### POST /auth/login

```json
{
  "email": "user@example.com",
  "password": "securePassword123"
}
```

#### POST /auth/register

```json
{
  "email": "user@example.com",
  "password": "securePassword123",
  "name": "John Doe"
}
```

## 6. Коммуникации (Communications)

### Эндпоинты

| Метод | Путь                | Описание                            | Права доступа       |
| ----- | ------------------- | ----------------------------------- | ------------------- |
| GET   | /chats              | Получение списка чатов пользователя | AUTHENTICATED       |
| GET   | /chats/:id          | Получение данных конкретного чата   | CHAT_PARTICIPANT    |
| POST  | /chats              | Создание нового чата                | AUTHENTICATED       |
| GET   | /chats/:id/messages | Получение сообщений чата            | CHAT_PARTICIPANT    |
| POST  | /chats/:id/messages | Отправка сообщения в чат            | CHAT_PARTICIPANT    |
| GET   | /requests/:id/chat  | Получение чата по запросу           | REQUEST_PARTICIPANT |

### Параметры запросов

#### GET /chats/:id/messages

- `page`: номер страницы (по умолчанию 1)
- `limit`: количество элементов на странице (по умолчанию 50, максимум 100)
- `before`: получение сообщений до указанной даты (опционально)

#### POST /chats/:id/messages

```json
{
  "content": "Здравствуйте, у меня есть вопрос по проекту",
  "attachments": [] // опционально
}
```

## Заключение

Представленная структура эндпоинтов обеспечивает полный набор операций CRUD для всех ключевых сущностей системы Happyness. Эндпоинты спроектированы с учетом принципов REST и обеспечивают четкое разделение ответственности между различными ресурсами.

Все эндпоинты должны соответствовать стандартам форматирования ответов и обработки ошибок, описанным в соответствующих документах API-контрактов.
