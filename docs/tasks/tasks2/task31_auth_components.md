## Обзор системы

Система аутентификации Happyness построена на основе современных подходов к безопасности с использованием JWT (JSON Web Tokens) и предоставляет полный цикл управления аутентификацией пользователей, включая регистрацию, вход, получение информации о текущем пользователе и безопасное управление сессиями.

## Основные компоненты

### 1. Серверная часть (Backend)

#### 1.1. AuthModule

Центральный модуль, объединяющий все компоненты аутентификации на сервере.

**Ответственности:**

- Конфигурация JWT и стратегий аутентификации
- Подключение и экспорт сервисов аутентификации
- Регистрация контроллеров аутентификации

#### 1.2. AuthService

Сервис, предоставляющий бизнес-логику для аутентификации.

**Ответственности:**

- Валидация учетных данных пользователей
- Создание и проверка JWT токенов
- Регистрация новых пользователей
- Хеширование и проверка паролей
- Управление refresh токенами

#### 1.3. JwtStrategy

Стратегия для проверки JWT токенов.

**Ответственности:**

- Извлечение токена из запроса
- Валидация токена
- Извлечение данных пользователя из токена

#### 1.4. LocalStrategy

Стратегия для аутентификации по email и паролю.

**Ответственности:**

- Валидация учетных данных пользователя
- Проверка пароля

#### 1.5. TokenService

Специализированный сервис для управления токенами.

**Ответственности:**

- Генерация access и refresh токенов
- Валидация токенов
- Ротация токенов
- Инвалидация токенов при выходе из системы

#### 1.6. TokenRepository

Репозиторий для хранения и управления refresh токенами.

**Ответственности:**

- Сохранение refresh токенов в базе данных
- Поиск токенов по идентификатору
- Удаление устаревших токенов
- Инвалидация токенов

#### 1.7. AuthGuards

Гварды для защиты маршрутов на основе аутентификации.

**Ответственности:**

- JwtAuthGuard - защита маршрутов, требующих аутентификации
- LocalAuthGuard - защита маршрута входа
- RolesGuard - защита маршрутов на основе ролей пользователя

#### 1.8. AuthController

Контроллер, предоставляющий API эндпоинты для аутентификации.

**Ответственности:**

- Обработка запросов на регистрацию
- Обработка запросов на вход
- Обработка запросов на обновление токена
- Обработка запросов на выход из системы
- Предоставление информации о текущем пользователе

### 2. Клиентская часть (Frontend)

#### 2.1. AuthProvider

Контекст-провайдер для управления состоянием аутентификации.

**Ответственности:**

- Предоставление контекста аутентификации всему приложению
- Управление состоянием аутентификации
- Предоставление методов для входа, выхода и регистрации

#### 2.2. TokenManager

Утилита для работы с токенами на клиенте.

**Ответственности:**

- Безопасное хранение токенов
- Автоматическое обновление токенов
- Извлечение информации из токенов
- Определение срока действия токенов

#### 2.3. AuthAPI

API-клиент для взаимодействия с серверными эндпоинтами аутентификации.

**Ответственности:**

- Выполнение запросов на регистрацию, вход и выход
- Обновление токенов
- Получение информации о текущем пользователе

#### 2.4. AuthGuard

Компонент для защиты маршрутов на клиенте.

**Ответственности:**

- Перенаправление неаутентифицированных пользователей
- Проверка прав доступа на основе ролей

## Взаимосвязи между компонентами

1. **AuthModule** конфигурирует и объединяет **JwtStrategy**, **LocalStrategy**, **AuthService** и **AuthController**
2. **AuthService** использует **TokenService** для генерации и проверки токенов
3. **TokenService** использует **TokenRepository** для хранения и управления refresh токенами
4. **AuthGuards** используют стратегии для защиты маршрутов
5. **AuthController** использует **AuthService** для обработки запросов
6. На клиенте **AuthProvider** использует **TokenManager** и **AuthAPI** для управления аутентификацией
7. **AuthGuard** использует **AuthProvider** для проверки аутентификации и разрешений

## Интеграция с другими модулями системы

1. **UsersModule** предоставляет информацию о пользователях, необходимую для аутентификации
2. **AuthService** интегрируется с **UsersService** для проверки учетных данных и создания новых пользователей
3. **Guards** используются в других модулях для защиты маршрутов
4. **AuthProvider** предоставляет информацию о текущем пользователе другим компонентам приложения

## Схема взаимодействия компонентов

Компоненты системы аутентификации взаимодействуют между собой согласно следующей схеме:

```
+----------------------------------------------+             +--------------------------------------+
|                  FRONTEND                    |             |              BACKEND                 |
+----------------------------------------------+             +--------------------------------------+
|                                              |             |                                      |
|  +-------------+       +------------------+  |  HTTP/API   |  +--------------+  +------------+   |
|  |   Auth      |<----->|  AuthService     |<-|------------>|  |AuthController|->|AuthService |   |
|  |  Components |       |  (API клиент)    |  |             |  |              |  |            |   |
|  +-------------+       +------------------+  |             |  +--------------+  +------+-----+   |
|        |                       ^             |             |                          |          |
|        v                       |             |             |                          v          |
|  +-------------+       +------------------+  |             |  +--------------+  +------------+   |
|  |    Auth     |<----->|   TokenService   |  |             |  | JWT Strategy |  |TokenService|   |
|  |   Context   |       |                  |  |             |  |              |  |            |   |
|  +-------------+       +------------------+  |             |  +--------------+  +------+-----+   |
|        |                                     |             |         ^                |          |
|        v                                     |             |         |                v          |
|  +-------------+       +------------------+  |             |  +--------------+  +------------+   |
|  |    Auth     |------>| Protected Route  |  |             |  | JWT AuthGuard|  |  Database  |   |
|  |   Guard     |       |   Component      |  |             |  |              |  |            |   |
|  +-------------+       +------------------+  |             |  +--------------+  +------------+   |
|                                              |             |                                      |
+----------------------------------------------+             +--------------------------------------+
```

### Ключевые взаимодействия

1. **Регистрация и вход в систему**

   - Frontend AuthComponents → Frontend AuthService → Backend AuthController → Backend AuthService → TokenService → Database
   - Обратный путь: Database → TokenService → AuthService → AuthController → Frontend AuthService → AuthComponents → AuthContext

2. **Проверка защищенных маршрутов на клиенте**

   - Router → AuthGuard → AuthContext → Protected Route Component

3. **Доступ к защищенным ресурсам API**

   - Frontend AuthService → Backend Controller → JWT AuthGuard → JWT Strategy → Endpoint Handler

4. **Обновление токенов**

   - Frontend AuthService/TokenService → Backend AuthController → Backend AuthService → TokenService → Database
   - Обратный путь с новыми токенами

5. **Выход из системы**
   - Frontend AuthComponents → Frontend AuthService → Backend AuthController → Backend AuthService → TokenService (инвалидация) → Database
   - После успешного выхода: Frontend AuthContext (очистка состояния) → Router (редирект на страницу входа)

### Обмен данными между компонентами

**Frontend:**

```typescript
// Пример обмена данными между компонентами на фронтенде
interface AuthContextType {
  user: User | null;
  isAuthenticated: boolean;
  isLoading: boolean;
  login: (credentials: LoginCredentials) => Promise<void>;
  register: (userData: RegisterData) => Promise<void>;
  logout: () => Promise<void>;
  refreshTokens: () => Promise<void>;
}

// Использование в компонентах
const { user, isAuthenticated, login, logout } = useAuth();
```

**Backend:**

```typescript
// Пример обмена данными между сервисами на бэкенде
interface AuthResult {
  user: User;
  tokens: {
    accessToken: string;
    refreshToken: string;
  };
}

// Взаимодействие между сервисами
@Injectable()
export class AuthService {
  constructor(
    private usersService: UsersService,
    private tokenService: TokenService
  ) {}

  async validateUser(email: string, password: string): Promise<User | null> {
    const user = await this.usersService.findByEmail(email);
    if (user && (await bcrypt.compare(password, user.password))) {
      return user;
    }
    return null;
  }

  async login(user: User, deviceInfo: string, ip: string): Promise<AuthResult> {
    const tokens = await this.tokenService.generateTokens(user, deviceInfo, ip);
    return { user, tokens };
  }
}
```

### Механизмы обеспечения безопасности

1. **Проверка токенов**

   - Frontend: Перехват запросов через axios interceptors для добавления токенов и обработки ошибок
   - Backend: Guard и Strategy для валидации токенов перед доступом к защищенным ресурсам

2. **Обновление токенов**

   - Проактивное обновление при приближении истечения срока действия
   - Реактивное обновление при получении ошибки 401

3. **Многоуровневая защита**
   - Frontend: AuthGuard для защиты маршрутов
   - Backend: Комбинация Guards для разных типов защиты (JWT, Roles, Permissions)
   - Database: Индексы и ограничения для оптимизации запросов и обеспечения целостности данных
