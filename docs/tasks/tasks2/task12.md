## Содержание задачи
- [ ] Разработать базовую структуру API-эндпоинтов

* **Контекст и Цель:** Разработать базовую структуру REST API с использованием NestJS, определить основные эндпоинты для взаимодействия с сущностями системы и реализовать первичную валидацию входных данных для обеспечения правильного взаимодействия клиентских приложений с сервером.

* **Ожидаемый Результат / Детализированные подзадачи:**
  - [ ] Настроить базовую структуру для REST контроллеров (Сложность: Средняя)

    - **Выход:** Скелетная структура контроллеров с базовыми эндпоинтами 
    
  - [ ] Реализовать контроллеры для работы с базовыми сущностями (Сложность: Средняя)
    - **Вход:** Модели данных из задачи 1.1
    - **Выход:** Контроллеры с CRUD-эндпоинтами для User, Company
    
  - [ ] Внедрить первичную валидацию входных данных (Сложность: Низкая)
    - **Вход:** Требования к формату и ограничениям данных
    - **Выход:** Валидаторы и DTO для проверки входящих запросов
  
  - **Вход:** Требования к API из ТЗ (Раздел 7), модели данных из задачи 1.1
  - **Выход:** Базовая структура API с контроллерами и валидацией

* **Технологические Указания:**
  - Использовать NestJS для создания REST API
  - Применить принцип Resource-Based API для организации эндпоинтов
  - Реализовать валидацию с помощью class-validator и class-transformer
  - Обеспечить типизацию DTO с помощью TypeScript

* **Нефункциональные Требования:**
  - API должен следовать принципам REST
  - Обеспечить консистентный формат ответов для всех эндпоинтов
  - Реализовать эффективную обработку ошибок с информативными сообщениями

* **Итеративность:** Начать с базовых CRUD-операций, затем расширять API для более сложных сценариев.

* **Формат Вывода:** Набор NestJS-контроллеров с CRUD-эндпоинтами для базовых сущностей, организованных по принципу Resource-Based API. Должны быть реализованы DTO-классы для типобезопасной валидации входных данных и генерации документации. API должен быть структурирован в соответствии с REST-принципами, иметь единообразный формат ответов и эффективную обработку ошибок.

* **Вопросы для Уточнения:**
  - Какие именно форматы данных нужно поддерживать (JSON, XML)?
  - Требуется ли версионирование API?
  - Нужны ли специализированные эндпоинты помимо CRUD?
  - Какие требования к формату ответов API, включая обработку ошибок?
